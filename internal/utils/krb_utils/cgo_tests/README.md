# CGO Kerberos Renewal Tests

This directory contains integration tests for Kerberos ticket renewal functionality using the Go CGO implementation.

## Files

- **test_renewal.sh** - Shell script to test ticket creation and renewal
- **test_renewal.go** - Go program for creating and renewing tickets
- **test_renewal_program** - Compiled binary (generated by test script)

## Prerequisites

1. **Kerberos Environment**:
   - Access to a Kerberos KDC (Key Distribution Center)
   - Valid Kerberos principal and password
   - MIT Kerberos utilities installed (`klist`)

2. **Environment Variables**:
   ```bash
   export KRB5_TEST_USERNAME='your-username'
   export KRB5_TEST_PASSWORD='your-password'
   export KRB5_TEST_DOMAIN='EXAMPLE.COM'
   ```

## Running the Tests

### Quick Test

```bash
# Set your credentials
export KRB5_TEST_USERNAME='webapp01'
export KRB5_TEST_PASSWORD='YourPassword123'
export KRB5_TEST_DOMAIN='CONTOSO.COM'

# Run the test
./test_renewal.sh
```

### What the Test Does

The test script performs the following steps:

1. **Create Initial Ticket** - Creates a Kerberos ticket with 7-day renewable lifetime
2. **Verify with klist** - Captures initial ticket details
3. **Wait 5 seconds** - Ensures timestamps will differ after renewal
4. **Renew Ticket** - Calls the Go renewal function (equivalent to `kinit -R`)
5. **Verify Renewal** - Checks that:
   - Ticket cache still exists
   - Ticket is readable and valid
   - `klist -s` passes (ticket validity check)
6. **Compare Outputs** - Shows differences between initial and renewed tickets
7. **Check Flags** - Displays ticket flags with `klist -f`

## Manual Testing

You can also use the `test_renewal_program` directly:

### Create a Renewable Ticket

```bash
# Build the program
cd internal/utils/krb_utils
go build -o cgo_tests/test_renewal_program cgo_tests/test_renewal.go

# Create ticket
./cgo_tests/test_renewal_program create \
    webapp01@CONTOSO.COM \
    'YourPassword123' \
    /tmp/my_krb5cc \
    604800  # 7 days renewable
```

### Renew an Existing Ticket

```bash
# Renew (no password needed!)
./cgo_tests/test_renewal_program renew /tmp/my_krb5cc
```

### Check the Ticket

```bash
# View ticket details
klist -c /tmp/my_krb5cc

# Check validity
klist -s -c /tmp/my_krb5cc && echo "Ticket is valid" || echo "Ticket is invalid"

# View flags
klist -f -c /tmp/my_krb5cc
```

## Ticket Flags

When viewing tickets with `klist -f`, you'll see flags like:

- **F** - Forwardable
- **R** - Renewable
- **I** - Initial (obtained with password, not renewed)

After renewal, the **I** flag will be cleared, indicating the ticket was renewed rather than initially obtained.

## Troubleshooting

### "Failed to renew ticket: KRB5KRB_AP_ERR_TKT_EXPIRED"

The ticket has expired and can no longer be renewed. Create a new ticket with a password.

### "Failed to resolve cache: No such file or directory"

The cache file doesn't exist. Create a ticket first before trying to renew.

### "Ticket is not renewable"

The initial ticket was created without a renewable lifetime. When creating the ticket, ensure `RenewableLife` is set to a positive value (typically 604800 seconds = 7 days, which is the common maximum).

### Timestamps Don't Change

Some Kerberos KDCs may not update timestamps on renewal if the ticket hasn't aged significantly. This is normal behavior. The important verification is that `klist -s` still passes after renewal.

## Security Notes

- **Never commit credentials** to version control
- Use environment variables for sensitive data
- The test script cleans up temporary files on exit
- Ticket cache files are created with 0600 permissions (owner read/write only)

## Integration with CredentialsFetcher

This renewal functionality can be integrated with the existing `RenewKerberosTicket` method in `internal/auth/kerberos/krb_client.go`:

```go
// Replace shell-based renewal
func (c *Client) RenewKerberosTicket(ctx context.Context, krbFilePath string) error {
    config := &krb_utils.KinitConfig{
        CCachePath:  krbFilePath,
        RenewTicket: true,
        Verify:      true,
    }
    return krb_utils.GenerateKerberosTicket(config)
}
```

This eliminates the need to shell out to `kinit -R` while providing better error handling and consistency with the rest of the codebase.
